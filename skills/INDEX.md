# Skills index

Always in context. When a row's *fires when* matches the task, Call the Skill tool with "<name>" and follow the skill. Generated by `scripts/gen-index.py`; do not edit by hand.

| Skill | Fires when | Does NOT fire when |
| --- | --- | --- |
| angular | Write, review, or fix Angular code (17+, standalone, signals, zoneless, SSR, Material, NgRx), or interpret an Angular tell: NG0100, NG0203, NG0201, NG0302, NG8001/NG8002, NG05xx hydration, NG0600, NG0950, NG0955/NG0956, NG01203, NG05104, a zoneless view that stops updating, CommonJS bailout, budget exceeded. Use when angular.json or @angular/core is present | While the failing layer is unknown (error-triage first); npm/Node-runtime failures (ERESOLVE, heap OOM, Node version) belong to nodejs |
| api-debugging | Reproduce one failing HTTP call with curl and read its status, headers, body and request ID. Use when a named endpoint fails with the request in hand: "works in Postman but not in code", 401/403/404/415/422/429 with a body, CORS, "need the request ID for support" | With no request and the layer unknown (error-triage), once the fault is in your own handler (debug-from-raw-logs), or to file it (bug-report-writing) |
| bug-report-writing | Write a bug report someone else will act on: a GitHub/GitLab issue upstream, a ticket for another team, a vendor support case. Use when the user asks to "file", "report", "open an issue for", or "write up" a bug for people who cannot see this conversation | When the goal is to diagnose or fix it here: error-triage owns an unclassified error, debug-from-raw-logs the investigation |
| context-hygiene | Control what enters the context window and when to compact. Use at the start of a task touching more than 5 files or any file over 200 lines, when a tool result exceeds 100 lines, before tests, builds, or log scans, and past 60% of the auto-compact window (check /context) | For the wording or length of the reply (token-optimizer) or for writing a subagent's brief (structured-prompting) |
| debug-from-raw-logs | Diagnose a reported bug from raw evidence: unedited trace, a repro that goes red, bisect, falsifiable hypotheses. Use for a crash, failing or flaky test, or "it doesn't work" in a known layer when the fix would otherwise be guessed | With the layer unknown (error-triage first), when a stack table names the tell (java-spring-stack, nodejs, python-django, angular, flutter-dart, react, react-native), or the cause is unambiguous |
| dependency-troubleshooting | Fix a dependency problem in any stack: an install that passes on one machine and fails on another, a lockfile in merge conflict or drifting between machines, two versions of one package in the tree, or a runtime tell naming a version mismatch (`NoSuchMethodError`, `cannot import name`, `NODE_MODULE_VERSION`) | For a tell with its own stack row (ERESOLVE: nodejs; `version solving failed`: flutter-dart) or an unclassified error (error-triage) |
| documentation-writing | Write a document people will act on: a README, quickstart, ADR, runbook, onboarding or CONTRIBUTING page, config reference. Use when asked to "document this", "write a README", "add a runbook for", "record the decision", "update the docs", or when "how do I run this" has no answer in the repo | For a bug report (bug-report-writing), a prompt or CLAUDE.md block (structured-prompting), or to shorten a reply (token-optimizer) |
| error-triage | Classify an error by failing layer (network, auth, config, code, data) and run one diagnostic to confirm it. Use when an error, status code, or "it fails" report has unknown cause: timeouts, 4xx/5xx, "connection refused", "permission denied" | Once the layer is known: java-spring-stack, nodejs, python-django, angular, flutter-dart, react, react-native, api-debugging (request in hand) or debug-from-raw-logs owns it; wrong 200 content: structured-prompting |
| estimation-and-scoping | Estimate a piece of work as a range with its scope and unknowns named. Use when asked "how long will this take", "estimate", "scope this", "break this work down", "t-shirt size", "story points", "can we do it this sprint", or "is this feasible" | To split a file or function (safe-refactoring), to record the decision afterwards (documentation-writing), or to do the work itself |
| flutter-dart | Write, review, or fix Flutter or Dart code, or interpret a Flutter tell: "A RenderFlex overflowed", "Vertical viewport was given unbounded height", "setState() called after dispose()", "Null check operator used on a null value", "version solving failed", MissingPluginException, Gradle/AGP mismatch, jank. Use when pubspec.yaml lists a flutter sdk dependency | While the layer is unknown (error-triage first); the API belongs to java-spring-stack, nodejs, python-django; React Native to react-native |
| incident-response | Run a production incident: declare severity, mitigate before diagnosing, update on a cadence, then root-cause and write the postmortem. Use when users are affected now: "the site is down", "prod is broken", a page or alert fired, error rate or latency jumped after a deploy, "we need a postmortem" | For one failing call with no user impact (error-triage), a runbook (documentation-writing), or an upstream report (bug-report-writing) |
| java-spring-stack | Write, review, or fix Java / Spring Boot / Hibernate-JPA / JAX-RS / JAX-WS code, or interpret a Spring tell: LazyInitializationException, N+1 query storms, @Transactional not rolling back, javax→jakarta compile errors, Jackson serializing a Hibernate proxy, HikariCP pool exhaustion. Use when pom.xml or build.gradle names org.springframework.boot, hibernate-core, jersey, or cxf | While the failing layer is unknown (error-triage first); nodejs, python-django, and angular own their stacks |
| log-instrumentation | Add or review logging: events, levels, fields, JSON output, request ID on every line, no secrets. Use when asked to "add logging", "log this", "logs are too noisy", "can't find the request in the logs", or when a new handler, job or outbound call has no log line at its boundary | To find a bug now (error-triage, debug-from-raw-logs) or to cap log output in context (context-hygiene) |
| nodejs | Write, review, or fix Node.js code, or interpret a Node tell: ERR_REQUIRE_ESM, ERR_MODULE_NOT_FOUND, ERR_PACKAGE_PATH_NOT_EXPORTED, "__dirname is not defined", UnhandledPromiseRejection, MaxListenersExceededWarning, ERESOLVE, heap out of memory, event-loop lag, SIGTERM ignored. Use when package.json, .nvmrc, or .node-version is present and the code runs in Node | While the failing layer is unknown (error-triage first); UI code belongs to angular, react, react-native; backends to java-spring-stack, python-django |
| performance-profiling | Measure before optimizing: baseline p50/p95, profile to the frame or query, change one thing, re-measure. Use when a request, page, job, build, or test suite is "slow", "takes forever", "got slower", or a CPU or memory graph climbs, with no stack tell naming the cause | When it fails or times out (error-triage), for one curl timing (api-debugging), or to keep duration lines (log-instrumentation) |
| python-django | Write, review, or fix Django code (Django, DRF, Celery/ASGI), or interpret a Django tell: ImproperlyConfigured settings, AppRegistryNotReady, "no such table", "Conflicting migrations", SynchronousOnlyOperation, TransactionManagementError, NoReverseMatch, TemplateDoesNotExist, staticfiles manifest entry, CSRF "Origin checking failed", DisallowedHost, naive datetime, hundreds of identical SELECTs. Use when manage.py, settings.py, or django in requirements/pyproject is present | While the failing layer is unknown (error-triage first); nodejs, java-spring-stack, and angular own their stacks |
| react | Write, review, or fix React code (19.x hooks, Server Components, React Compiler, Next.js, Vite) or a tell: "Rendered more hooks than during the previous render", "Maximum update depth exceeded", "Hydration failed because the server rendered HTML", "Invalid hook call", "not wrapped in act(...)". Use when package.json lists react-dom | While the failing layer is unknown (error-triage first); npm failures belong to nodejs, Angular to angular, mobile to react-native |
| react-native | Write, review, or fix React Native code (0.76 to 0.87, New Architecture, Expo SDK 54 to 57, Metro, Hermes) or a React Native tell: "Unable to resolve module", "TurboModuleRegistry.getEnforcing", "requireNativeComponent", "Mismatch between JavaScript part and native part", "No bundle URL present". Use when package.json lists react-native | While the failing layer is unknown (error-triage first); web React belongs to react, npm failures to nodejs |
| response-self-review | Check a finished draft against evidence before sending. Use when the draft asserts a result not seen in tool output this turn ("tests pass", "fixed", a count, a version, "updated the README"), contains a code or file change, or answers a multi-part request or an explicit format or length constraint | For one-line replies, to trim length (token-optimizer), or to validate a prompt for another model (structured-prompting) |
| safe-refactoring | Change code structure while behaviour stays identical: rename, extract, inline, move, split a file, delete dead code, migrate call sites, or anything the user calls "refactor", "clean up", "simplify", "reorganise", "break up", "modernise". Use for the step size, the proof that nothing changed, and the commit discipline | To change what the code does or how fast (the stack skill, performance-profiling) or once a step goes red (debug-from-raw-logs) |
| structured-prompting | Author or fix a prompt another model will run: a system prompt, template, subagent brief, tool description, or CLAUDE.md block. Use when asked for one, or when a prompt-driven output is wrong in a repeatable way (wrong shape, ignored rule, injected instruction) | To do the task yourself, when the model call itself fails (error-triage), to shape your own reply (token-optimizer), or for what a session reads (context-hygiene) |
| token-optimizer | Choose the cheapest output form and how to report tool output, keeping everything the user must act on. Use when the user wants brevity or lower cost, when a reply would include more than 20 lines of code or tool output already in context, or would exceed 150 lines | For what to read or when to compact (context-hygiene), tutorials, or a self-contained handover (bug-report-writing) |
